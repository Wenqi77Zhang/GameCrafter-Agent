## 结论

核心功能已有代码，但尚不能交付为“别人拿到链接就能稳定使用”的正式产品。
目前最重要的是内容质量和同一版本的完整验收，不增加 Agent 数量或继续扩展辅助功能。
本次核查没有开放公网、部署到公司服务器、修改真实项目数据或授予人工批准。

“演示”分为三个层级，不能互相替代：

| 层级 | 范围 | 当前判断 |
|---|---|---|
| 作者在场的本地技术展示 | 展示来源、证据、任务、模型失败与人工修改；说明局限 | 可以展示已有能力，但须先启动服务并准备真实可读案例，不称正式发布 |
| 邀请他人试用的展示版 | 非开发者按界面独立完成一份营销稿；账户受控、可恢复 | 尚未达到；需关闭下列 D1–D4 |
| 公开互联网服务 | 陌生用户可登录上传资料并运行任务 | 尚未达到；除 D1–D4 外还要完成 P1–P4，现有 Compose 不能直接映射为公网服务 |

## 公开上线额外关口

| 编号 | 工作 | 已有基础与仍需补齐的部分 |
|---|---|---|
| P1 身份与网络 | 域名/TLS、Secure Cookie、精确 Origin、强凭据、服务端限流 | 已有本地账号、RBAC、CSRF、登录限流和安全响应头；Compose 默认关闭认证、HTTP、仅监听回环地址。必须明确启用并在实际反向代理后验证，数据库与 Ollama 不得公开 |
| P2 数据隔离与权限 | 最小权限数据库账户、跨项目隔离、私有资料生命周期与删除 | 已有隔离和备份/删除逻辑；当前本地 purge 依赖数据库拥有者及 `session_replication_role`，托管环境需窄权限删除方案；官方源 DNS 校验与实际连接间的绑定仍待加固 |
| P3 运维与容量 | 监控告警、备份和恢复演练、回滚、任务资源配额、故障处理责任 | 已有 worker 心跳、关联请求 ID、重试与预算；尚无本次服务器上的持久运行、负载、灾难恢复证据；模型耗时和显存必须实测 |
| P4 发布安全与用户告知 | 全部依赖/镜像安全复核、隐私说明、素材/模型许可核对、受控试用反馈 | 本轮补齐开发工具安全修补后，前端全依赖审计未发现已知漏洞；不代表 Python、镜像、默认分支或全系统已完成安全审计；不承诺自动发布、成片、营销效果或商业 SLA |

公开部署仍需独立确认目标环境与开放范围。不会因为公司有服务器，就自动把本地单用户
模式公开给陌生用户。无付费模型自动回退的边界保持不变。

  未单独指定时仍沿用知识模型，不悄悄换成更大的模型。
