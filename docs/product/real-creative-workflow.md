更新：2026-09-11。部署暂缓；这是一次对现有个人作品的实质修正，不是商业成熟度认证。
此前 M18 的知识审核定位与已提交状态修改已保留。本轮没有重置个人数据库。

**当前结论：工程链路已落地，生成质量尚未达到无人值守交付标准。**
最新真实模型审核为 14 例各重复 2 轮，20/28 次符合预期，仍有 6 次漏报与 2 次误报。

## 这次解决的核心问题

| 原问题 | 当前处理 |
|---|---|
| 规则拼接的方向被当成真正营销方案 | 移除页面中重复的模板方向和模板拍摄结构；只保留选题、规格和证据摘要；主要建议来自真实模型 |
| 模板填充被称为脚本生成 | 新建真实 Ollama 写作任务；旧接口明确叫手动脚手架，不伪造模型来源 |
| 自动修订只是重置模板 | 根据当前稿与评审问题实际重写，保存新版本；没有变化就报错，不扣已保存版本预算 |
| 填完字段就得到高分 | 时长、语速、字幕和引用做规则检查；语义判断另一次调用，不能看到规则分以免被误导 |
| 模型遗漏字段却给出“没有问题” | 每段文案必须有三分类判断；漏段、越界引用、伪造证据原句均拒绝保存评审 |
| 模型误判被呈现为确定事实 | 显示被质疑的草稿原句，标注“模型发现风险 / 修改建议”，提醒回到证据核对，不照搬错误改名 |
| 修改、拒绝后仍可能导出旧批准稿 | 绑定当前检查规则、最新评测与该评测对应的最终决定；后续拒绝撤销导出资格 |
| 前端不知道提交是否成功 | 审核理由预设选择，提交后折叠并显示已提交；更改决定才重新展开 |
| 不知道审核在质疑哪里 | 显示“需核对 / 全部”，按字段展示原句和证据；一键展开编辑器并选中原句 |
| 编辑后的新稿刷新又回到旧稿 | 恢复任务时比较服务端最新版本；旧模型完成记录不覆盖更新的人工修改版本 |
| 不同实体或地区的事实混用 | 创作上下文包含冻结实体修订、别名、语言、地区和游戏版本；模型仍可能误用，界面展示范围 |
| 结构化事实显示成 object 占位文字 | 读取实际已审核文本，带实体名和适用范围展示；窄屏编辑器标签独立成行 |
| 编辑需要写 JSON | 逐镜表单、事实复选框、标题/文案/标签编辑；刷新不抹掉未保存输入 |
| 重试或迟到结果覆盖新内容 | 阶段缓存、心跳续租、单调递增尝试号、取消和发布前版本比较 |
| 备份遇到事实置信度无法序列化 | Decimal 无损转换并在恢复时验证，增加完整创作与知识备份往返测试 |

来源、知识、趋势、GDD、账户与团队权限仍复用现有服务，不另建一套聊天系统、向量库或消息队列。
GDD、账户、运行记录是辅助工具；脚本已有版本时，重复创建工作流的设置默认折叠。

## 最终产物和真实性

营销建议是待验证的创意假设，不是已验证的市场结论。新闻来源不等于 TikTok 热度，
人工记录的标签数量不等于可用视频素材数量。规则分反映匹配或结构，不预测播放量。

脚本是英语五镜稿，包含时间、口播、字幕、画面要求和事实引用。输出不是视频成片。
只提供名称、厂商或类型时，系统说明资料不足，要求补充玩法、世界、角色内容或更新事实。
这类基础资料可以辅助人工写作，但不足以支持自动营销策划，更不能推演为具体机制。

模型失联、超时、长度截断、结构错误或引用越界都会明确失败；不会转付费接口、假数据或模板。
完整 JSON 的结构/语言错误最多额外修复一次，两次调用均计入实际已报告用量。
传输失败的未知用量标为不完整，不宣称零 token。

## 模型与架构选择

当前为 5 个模型角色 + 3 个确定性工具角色，由一个持久化 Harness 控制：

1. Knowledge Curator 提取候选事实；Knowledge Reviewer 独立预审，人工批量确认或处理疑难项。
2. 来源工具采集与保全证据；趋势工具做清洗和解释匹配；GDD 工具做结构整理。
3. Campaign Strategist 生成建议，Quality Critic 独立核查，用户决定选题。
4. Script Writer 生成/修订，Quality Critic 独立评审，规则检查后交人工终审。

这叫受约束的工作流和有界“生成—检查—修订”，不是无限互聊、ReAct 或自动学习。
不保存隐藏思维过程，不允许模型自行扩大权限、改变知识版本、批准自己或发帖。
模型可以相同，但调用上下文独立；这不能保证消除相关错误，仍需反例测试与人工关口。
详见 [系统架构 DAG](../architecture/system-architecture.md)。

默认继续使用已配置的 `GAMECRAFTER_OLLAMA_MODEL`。可单独设置：

```dotenv
GAMECRAFTER_CREATIVE_OLLAMA_MODEL=qwen3.5:9b
```

它只影响新创作任务，不改变知识提取模型，不下载权重，也不改变旧任务的冻结模型。
本轮在本机试验了 `qwen3.5:4b` 与 `qwen3.5:9b`；不能仅凭模型更大就宣称质量更高。
对照时发现低温度与重复的限制性示例会带来漏报、误报和提示内容混入评审。
写作采样以 [Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B) 的通用建议为起点，
审核用 temperature=0、presence_penalty=0，这是本项目实验设置，不是官方推荐或准确率保证。
开启思考曾耗尽限定输出预算，所以当前关闭。每次调用输出上限 3000 token，
上下文窗口 16384；结构修复最多一次，业务修订仍受工作流预算限制。

v10 将实际文案字段枚举成不截断的片段（最长 600 字符、最多 96 段），每批至多 8 段。
模型对每段给出 `SUPPORTED / UNSUPPORTED / NOT_A_FACT`、中文理由和引用事实原句。
控制层核验覆盖集合、引用集合、重复引用以及原句是否逐字属于所引用的已审核值；
不能把原始来源中的其他细节当成已审核事实，也不能用模型自己编的替代文案冒充修正。
每批最多一次格式修复；首 12 个阻断问题交给有界修订，界面保留全部逐段结论。
失败分组前已发生的调用同样计入用量。重试缓存仍以完整工作流阶段为单位。

设计参考细粒度核查思路（[FActScore 原论文](https://arxiv.org/abs/2305.14251)），但实际实现
是字段/长度分段，**不是论文的原子事实拆分或 FActScore 指标**。一段可能包含多个断言。
引文存在不等于推论成立，模型仍会把缺少证据的泛化误判为有支持，不能承诺自动放行可靠。

提示或评审规则升级后，不把旧结果自动当成新版通过；重新生成/评审不会删除历史。

## 安全、回溯和恢复

- 模型只访问受控本机 Ollama，不传私有资料到云端；外部页面和草稿始终是不可信数据。
- 创作输入冻结在项目数据库中，含所选知识事实和最小上下文，不是审计日志。
  模型审计记录只有角色、摘要、用量、耗时与状态，没有原始提示和秘密。
- 阶段成功后可复用已校验输出；评论失败不必再写一次。取消只取消保存资格，
  不保证立刻中断 Ollama 正在进行的计算。
- 后台保存前检查租约尝试号与最新脚本版本，旧 worker 或迟到模型不会覆盖人工修改。
- 审核引用必须来自实际草稿；知识引用必须属于冻结快照。内容是否真的蕴涵仍需语义审查。
- 不自动继承旧版评测资格，不把模型初审当作素材授权。最终负责人需确认素材权利与活动规则。

## 如何验收

1. 正常启动数据库、Ollama、API、worker 与网页。开发入口由启动终端给出，默认 5173；
   生产预览的 8080 是另一个运行方式，本轮不自动替换。启动失败先运行 `scripts/doctor.ps1`。
2. 使用已有项目和来源。知识页补足可讲述的事实，检查引文和地区/版本，处理左侧待办后发布知识版本。
   名称不足时不要反复点生成，按提示补资料并新建使用新知识版本的营销任务。
3. 营销页记录或检索真实话题，运行匹配。点“生成具体营销建议”，等写作和独立检查完成。
   你应看到明确的中文方向/话题、英语开场 A/B、拍摄步骤和验证方式，而不是只有分数。
4. 若建议未通过，展开错误查看原因与修改方向；不要把它当成已批准方案。
   检查合适选题后，点预设理由并提交。看到“已提交，无需重复处理”后不用再次操作这里。
5. 创作页生成英语脚本并评审。在“逐段证据核查”查看“需核对”，展开事实原句和来源；
   点“定位并编辑这句话”直接打开对应字段。切到“全部”可查看模型认为有支持/非事实的判断。
   选择支撑事实后保存新版本；模型可能误判，不要把所有修改建议当成新的游戏设定。
   页面应显示新版本、变化内容和重新评审要求。自动修订次数用完时改用编辑器，不会无限循环。
6. 重新评审后，负责人核对事实、口播和素材权利，选择终审理由再提交。只有该版本的当前检查及
   最终决定允许时，Markdown/JSON 导出才可用。导出文件应有实际稿件与来源，不是占位符。
7. 再改一个标题，确认导出资格不会被继承；刷新页面确认历史与新版本都在。
   切换英文和缩窄窗口，确认仍能找到下一步。

模型评审会出错。这个流程的目标是降低风险并让错误可发现、可修正，不是宣称“零幻觉”。
商业效果、多人真实使用和部署运行需要单独验收，不能由测试通过替代。
