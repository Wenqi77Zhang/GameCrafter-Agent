# GameCrafter：营销优先产品基线 v3

确认日期：2026-10-30。状态：产品方向与主流程已确认，运行代码尚未完成改版。
这里的 v3 是产品方案修订号，不是软件已发布的版本号。

本文件取代 `baseline-v2.md` 中的产品中心、默认游戏、资料入口和用户主流程。
旧文档与旧测试是历史记录，不能覆盖本次确认，也不能证明新流程已经实现。
本轮不更换仓库、不清空个人数据库、不抹除 Git 历史，不自动合并或公开部署。

## 1. 已确认的产品决定

- 服务独立游戏开发者和中小游戏团队，帮助他们决定宣传什么、面向谁、怎样表达。
- 不绑定《异环》或其他指定游戏；不再把维护某款大型游戏资料库作为产品主线。
- 用户可以不上传任何资料：只输入游戏名称，系统寻找官网与官方媒体。
- 存在同名游戏或官方身份不明确时，再请用户确认；同时保留补充链接和上传资料的入口。
- 官方检索与用户提供资料可以混合使用，不把上传 GDD 设为开始任务的前提。
- 没有公开页面的未发布游戏仍可使用用户提供资料；用户明确建立游戏身份，不伪装成已核验的官方站点。
- 第一次主要结果是最多三个可比较、有依据的营销方向；资料不足时不硬凑三个。
- 用户先选定方向并确认关键事实，再进入可编辑脚本的生成、评审和交付。
- 来源、知识和运行记录作为辅助信息按需展开，不要求用户先学会操作资料管理系统。

产品定义：**从游戏名称或现有资料出发，结合真实可核查的信息与趋势，
帮助小团队选择营销方向，再把选定方向写成可执行、可修改、可追溯的短视频脚本。**

## 2. 本次未改动的边界

- 个人长期作品，保留求职展示与后续商业化方向；不恢复五人四天任务限制。
- 默认简体中文界面，可切换英文；首先做好英语市场的 TikTok 短视频场景。
- 延续 US/UK/CA/AU/NZ 市场标签、潜在新玩家、曝光目标和约 30 秒英语脚本默认值；
  这些是可见、可调整的任务预设，不是根据游戏名称推断出的市场结论。
- Python 后端、现有 React 前端和数据库任务基座继续复用；不因改版增加微服务或 Agent 数量。
- 保留本地模型、零付费 API、无付费自动回退；不因自动检索承诺无限免费搜索或任意平台抓取。
- 私有资料不上传搜索引擎或云模型；不自动发布、不制作视频成片、不承诺营销效果。
- 选题和精确版本的最终批准仍由人作出；模型初审不是事实认证或素材授权。

## 3. 用户主流程与产物

| 阶段 | 用户看到什么 | 系统负责什么 | 何时需要用户 |
|---|---|---|---|
| 识别游戏 | 游戏名输入；可选链接/文件；可见的目标平台与市场预设 | 查找官方入口、核对名称和开发/发行主体，列出来源身份依据 | 同名、身份不明或无可用来源时 |
| 查看营销方向 | 最多三个方向卡，明显标注草案与不确定点 | 按任务范围取材，整理证据，分析真实可用趋势，生成并检查方向 | 比较方向；可调整目标或补充信息 |
| 选择与确认 | 选定方向及它真正依赖的关键事实、引文和风险 | 展示该任务的待确认项，保存人工选择和事实确认版本 | 选题与关键事实确认；冲突不能自动略过 |
| 编辑与交付 | 英语分镜、评审定位、修改前后差异、最终导出 | 有界写作/检查/修订，保存版本，绑定当前检查与最终决定 | 修改需要人工判断的内容，终审准确版本 |

每个方向卡至少说明：

1. 一句话的营销方向与具体话题，不仅是“玩法展示”等泛标签。
2. 目标受众、核心卖点和内容表达角度。
3. 推荐理由，以及它与其他方向的差异或取舍。
4. 游戏事实依据；有趋势依据时列明实际来源、观察时间、地区及适用限制。
5. 不确定点、需要确认的事实与素材需求；创意假设和已知事实不能混写。
6. 清晰的“选这个方向”操作；提交后显示已选，避免重复处理。

没有可讲述事实时，返回资料不足的具体原因和补充入口，而不是生成空泛方案。
没有相关或可用趋势时如实说明；游戏自身卖点方向可作为非热点草案，不能包装成“正在热门”。
有证据的一两个方向优于三个同义改写；不以方向数量、规则得分预测播放量。

## 4. 检索与证据边界

- “发现可能的入口”与“确认它是官方来源”是两个状态。名称相似、搜索排名或模型自信不足以认证官方身份。
- 保留官网与账号的关联依据、用户确认记录、来源 URL、采集时间、地区/版本和原文片段。
  “用户指定的来源”与“具有可核查官方关联的来源”分别标注。
- 只读取公开且允许访问的内容，限制页数、大小、时间、重定向与访问频率。
  不绕过登录、验证码或站点限制；有链接不等于已成功读取正文或视频内容。
- 通用接入不等于允许访问任意地址。保留 URL/协议/DNS/私网地址和重定向校验；
  用户确认来源身份也不能关闭这些网络安全限制。
- 多语言、跨地区、不同版本的证据不能无条件合并；发现矛盾就保留冲突与范围。
- 公网搜索只使用游戏名称及明确公开的检索线索；不能把私有上传文档拼进外部搜索查询。
- 官网资料不等于内部 GDD；官方信息可证明游戏描述，但不自动证明素材使用权或营销效果。
- 搜索供应方、可用免费额度和官方媒体接入方式尚未选定。必须验证真实接入，不以静态候选
  或模型生成的 URL 伪装搜索。检索不可用时显式失败并允许补链接，不能算自动检索验收通过。

## 5. 审核如何配合营销优先

方向预览可以使用有原文支持、尚待用户确认的候选事实，但必须显示其待确认状态；
身份未解决、证据缺失或冲突未解决的断言不能被当作确定卖点。
它不是已批准方案，不授权写作、最终交付或发布。

选择方向时集中呈现当前任务依赖的关键事实与冲突，确认后形成冻结的创作输入。
脚本只使用该输入内已确认的事实；编辑、撤回或换方向必须重新检查对应版本。
无关方向或其他任务的候选资料不应迫使用户逐页审核，但不能通过漏列本方向依赖来绕过风险。
这是要实现的新任务级确认设计；旧的全项目知识发布关口不会只改文案就被视为已替换。

保留服务端的引用、身份、版本、幂等和导出校验。前端少步骤，不等于后端少校验。

## 6. 功能取舍与迁移

| 内容 | 处理决定 | 完成依据 |
|---|---|---|
| 特定游戏的默认创建、别名、链接、来源卡 | 从活动产品入口移除，换成通用游戏识别 | 新工作区不自动创建任何指定游戏，不带旧案例默认值 |
| 专用官网适配器及默认 replay 路径 | 用通用安全来源注册/适配能力替代，再移除活动依赖 | 实际调用不导入旧专用模块，不指向旧 fixture |
| 旧案例绑定的测试与烟测 | 换成明确合成的通用样例、身份歧义反例与独立真实来源验收 | 不是全局替换游戏名；仍检查同等证据、失败和恢复行为 |
| 来源、知识、冲突等页面 | 降为资料与证据辅助视图，主流程按当前任务展示 | 用户无需手动来回切页才能找到待办、方向和提交结果 |
| 证据保全、持久任务、版本、审计、人工终审 | 复用并按新流程验证 | 引用、隔离、恢复、版本与批准不可绕过 |
| GDD 整理、账户与团队辅助模块 | 不扩展、不强迫进入主流程；保留已有安全与数据能力 | 不因界面简化删掉权限或破坏旧数据 |
| 旧数据库、原始资料、Git 历史、历史文档 | 不自动删除，不迁移为新游戏事实 | 可恢复、可区分历史与新流程；任何实体改绑需独立迁移验证 |

没有指定新的默认真实游戏。合成数据只验证工程行为，真实检索和实际营销产物必须另验收。
“彻底去掉案例绑定”指活动产品、配置和新验收不再依赖该案例，不是销毁用户历史资料。

## 7. 实施顺序与退出条件

| 批次 | 范围 | 退出条件 | 当前状态 |
|---|---|---|---|
| A | 固化定位、流程、取舍、架构目标与历史边界 | 唯一当前基线、README/路线图/架构指向一致 | 本次文档变更 |
| B | 通用游戏入口与官方来源发现 | 仅输入名称可真实发现来源；同名/伪官方/无结果/无法访问/私网 URL 可见且安全；上传不是必需 | 待实现 |
| C | 方向优先的工作区与任务级事实确认 | 1–3 个可比较方向有来源与不确定性；资料不足不凑结果；提交状态、待办与下一步明确 | 待实现 |
| D | 写作闭环与去案例化验收 | 所选方向及已确认事实正确传递；评审/编辑/重试/终审/导出绑定版本；活动路径不再依赖旧案例 | 待实现 |

每批先验证再进入下一批，不用“界面换名字”代替真实后端能力。
通用能力至少用两个不同游戏资料集验证，其中包括同名歧义和“没有用户上传资料”的路线；
真实检索、固定离线回归和模型内容质量分别留证，不把旧模型测试分数移植到新基线上。
方向的可读性、事实核对和新用户独立使用须人工验收，测试数量不是营销价值指标。

上线仍需要同一提交的数据库/浏览器/恢复验收和独立安全检查，不由本次方向确认自动授权。
旧 M19 状态仅作基础参考：[历史实现记录](real-creative-workflow.md)、[上线检查单](release-readiness.md)。

## 8. 后续变更规则

用户、平台/市场、资料外发、费用、人工批准或核心技术架构如需改变，先单独说明并确认。
不要把历史资料中的《异环》、知识库优先、六个角色或未落地框架当成本轮的新要求。
工程细节在上述边界内实施；自动检索、方向预览与现有服务之间的具体接口尚待设计与验证。
